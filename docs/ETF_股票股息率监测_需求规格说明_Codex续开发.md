## 1. 目标、范围与非目标

### 1.1 业务目标

为 ETF 与 A 股个股建立统一的**税前现金股息率**监测能力，支持：

- 查询证券最新价格、实际 TTM 股息率、年度参考股息率、已公告待派及预案信息。
- 通过证券代码/名称/简称检索，在 ETF 与股票页面各自管理自选，按股息率排序。
- 点击指标追溯价格分母、分红现金分子、分红事件、公告版本、证据文件和核验状态。
- 查询最近分红记录及完整历史，绘制逐交易日历史 TTM 股息率曲线。
- 用未来 90 天**已确认**除息日时间线跟踪自选标的，并支持手动刷新。
- 对缺失、过期、矛盾和口径不一致的数据作明确标记。

### 1.2 业务范围

| 对象 | 必需内容 | 特有差异 |
|---|---|---|
| ETF | 每份现金分红、近 12 个月派息次数、TTM / 年度参考 / 公告待派或预案、历史曲线 | 保留“每份 / 每 10 份”原始单位；处理基金份额拆分合并 |
| A 股股票 | 每股现金分红、TTM / 年度参考 / 公告待派或预案、历史曲线 | 保留“每股 / 每 10 股”原始单位；区分所属财年与实际除息年；处理送转、拆股等权益变化 |

### 1.3 非目标与保护要求

- 不增加券商交易、荐股、自动交易、组合管理、多用户、注册登录、云同步或推送系统。
- 不把“指数股息率监测”（例如中证红利指数股息率）、轮动策略、主线乖离率、纳指 ETF 溢价率等内容混入此模块；这些属于其他功能。
- 不新增一级导航；继续复用已有 `红利看板 → ETF股息率 / 股票股息率` 入口。
- 不改写沪深300红利/成长对比、三棱镜、资金流向、五年之锚等已有业务逻辑、API、CSV、数据库表和图表。
- 不为了完成本模块切换前端技术框架；维持现有轻量静态前端实现。
- 不在前端或公共静态目录暴露完整 SQLite 数据库、原始抓取缓存、凭证或内部证据档案。

## 2. 指标与计算合同（必须先固化）

### 2.1 数据基准

- 所有股息率以**税前现金分红**计算；展示单位为 `%`，内部计算用 `Decimal`，禁止用未经控制的浮点链路累计金额。
- 每笔分红必须保留：公告原始金额、原始单位、标准化每份/股金额、币种、除息日、公告披露日、分红所属年度（若适用）、事件状态和证据标识。
- 比较同一证券不同日期时，分子、分母必须处于**同一份额/股本基准**。出现公司行动时要调整旧分红，不能直接把历史每股派现金额和新的每股价格相除。
- 价格分母为观察日对应**未复权**每股/每份价格；与历史现金分红统一至该日股本/份额基准。若选择其他等价复权体系，必须完整论证并通过与该定义的逐日数值一致性测试，不允许混用。
- 展示价格日期、价格来源及数据更新时间。休市日取最近有效收盘价时，要显式显示该交易日，不冒充实时成交价。
- 股息率是现金派息/现价，不等于含分红再投资的全收益率，也不等于指数股息率。

### 2.2 TTM 实际现金股息率（主指标）

对观察日 `t`：

```text
TTM_cash_per_unit(t)
  = SUM(经权益调整至 t 口径的每份/每股实际现金分红)
    WHERE ex_date ∈ (t-365天, t]
      AND 该事件在所选信息查询模式下属于已经实施/除息的有效事件

TTM_yield_pct(t)
  = TTM_cash_per_unit(t) / unadjusted_close(t) * 100
```

必须满足：

1. TTM 是滚动 365 天窗口，左开右闭；不能用某一自然年累计派息替代。
2. 只有实际生效的派息进入 TTM；预案、修订中、待实施事件不得提前进入。
3. 经济分红事件按唯一 `event_id` 归并；预案→修订→实施为同一事件的不同公告版本，不能重复累计。
4. “零分红”与“尚未收集到完整历史分红”是不同状态：完整证明在窗口内无分红才可返回 `0`；否则返回 `null` 与具体原因。
5. 价格缺失、过期、除息日缺失、单位未解析、权益调整未核实或分红覆盖不足时不得生成看似精确的百分比。
6. 为生成某日的 TTM，必须提前获取该日以前至少 365 天的有效分红覆盖；为生成 5 年曲线，分红覆盖应早于曲线起点 365 天。

### 2.3 年度参考股息率（次指标）

```text
annual_reference_yield_pct
  = 某个已完整核验年度的税前现金分红合计（调整至观察日单位）
    / 观察日未复权价格 * 100
```

- **ETF**：默认采用上一完整自然年，按实际除息日归集；显示年度标签。
- **股票**：按明确的分红所属财年归集；同一财年可能有不同实施年份，不能仅用除息自然年筛选。
- 只在完整年度事件覆盖可证明时显示数值；否则 `null + reason`。
- 必须标记“年度历史分红 / 当前价格”的参考性质，不等同未来承诺收益率。

### 2.4 已公告待派、预案与预期（第三指标组）

要**分组展示，不得混算**：

| 类别 | 定义 | 显示规则 |
|---|---|---|
| 已公告待派 `CONFIRMED` | 已正式确认金额和预计/确定的实施安排，但尚未发生实际除息 | 显示公告金额、每股/份现金、已确认除息日（如有）、公告链接及“尚未实施” |
| 预案 `PROPOSAL` | 董事会或股东大会等阶段披露的分红计划，仍可能变化 | 显示计划进度、金额、披露日、是否存在确定除息日期；明确“预案非实际派息” |
| 股票估算 `ESTIMATE`（后续 P2） | 无有效预案且满足稳定支付率/明确分红承诺等条件时的情景估算 | 只针对股票，显著标注“估算”，不进入实际TTM或日历“已确认”列表 |

若需要展示“公告金额÷现价”的比值，应命名为**“本次公告派息/现价”**等，而非在没有周期证据时称为“未来12个月年化股息率”。允许展示某类公告的金额总额，但不得自动当作未来完整年度现金流。

股票 P2 估算逻辑沿用原需求：

```text
estimated_yield_pct = 预计现金分红支付率 × TTM归母净利润 / 当前总市值 × 100
```

前提：支付率的单位与比例清晰；净利润、总市值同口径、同观察基准；支付率估算与依据可追溯；出现支付率 >100% 等情形时明确风险提示。此功能**不是当前 D0/D1 放行的前置条件**。

### 2.5 两种历史查询模式

- `latest_verified`：使用当前已核验的最新历史事实重新计算，适合事实回看。
- `as_known`：只使用在历史观察时点 `known_at <= t` 已经公开可知的公告版本及对应行情，适合无前视偏差的历史策略研究。

两种模式的口径差异要在 API/页面标明；测试必须验证历史公告修订与补录不会“穿越”到过去。

## 3. 功能与页面需求

### 3.1 导航、检索及标的池

- 保留 `web/index.html` 中已有两个入口，分别打开 `?type=ETF` 和 `?type=STOCK`；页面逻辑可复用，但自选及查询结果必须按类型隔离。
- 页面顶部**常驻**搜索框，支持证券代码、名称、简称；尽可能支持拼音缩写；输入防抖、键盘/触摸选择与错误重试。
- 实现可更新的 A 股和场内 ETF **真实证券基础表**，覆盖用户可搜索范围；来源、更新时间、交易所、类型和失效状态可核验。
- 搜索结果明确代码、名称、市场与证券类型；不可用证券不能假扮可查询。
- 默认展示本地自选；可从查询或详情页加自选，在自选中移除；操作必须幂等并持久化到 SQLite。
- 搜索不是仅返回预置 `510880`、`600519` 两个样例，而是能检索完整的已配置证券池。

### 3.2 自选看板

默认表格列：

| 字段 | 要求 |
|---|---|
| 标的 | 代码、名称、市场、类型 |
| 最新价格 | 数值、涨跌幅、报价交易日和更新时间 |
| TTM 现金分红金额 | 逐事件求和的元/份或元/股，不是单次公告分红 |
| TTM 现金股息率 | 核心排序列；默认降序 |
| 最近/下一次除息日 | 已经发生的显示过去日期；已确认未来日期单独高亮 |
| 数据状态 | 正常、待更新、数据不完整、校验失败、功能建设中；可查看原因 |

- 支持单列升/降序切换、列头状态显示和排序偏好记忆（`localStorage` 可只保存 UI 偏好，不保存业务唯一数据）。
- 不可计算项单独排在有效数字后面，不能当 `0%` 参加排序。
- 窄屏固定证券标识列、横向滚动；宽屏充分展开。
- 支持单个查看、添加/取消自选、手动批量刷新和逐标的同步结果反馈。
- **预期/预案指标只在详情展示，不强制在自选表中增加新列**（遵循历史需求）。

### 3.3 单标的详情页

必须包含：

1. 标的名称、代码、市场、类型、当前价格/涨跌幅、价格日期、数据源和更新时间。
2. 三个并列指标卡：**TTM 主指标**、年度参考、已公告待派/预案；缺值展示“—”及原因。
3. 点击卡片查看完整计算链：观察日、口径、分子现金合计、价格分母、纳入事件、排除事件和原因、每次单位转换/权益调整、计算公式、数据质量状态与原始证据。
4. 最近 8 次分红事件，支持展开近 5 年记录：公告日、所属财年（股票）、股权登记日（如有）、除息日、每 10 股/份与每 1 股/份金额、派息状态、公告版本和来源。
5. ETF 专有：基金全称、每份现金派息、近 12 个月派息次数；股票按每股税前派现展示。
6. 1Y/3Y/5Y 历史 TTM 曲线（见 3.5），以及“数据仅供参考，不构成投资建议”的简短说明。
7. 校验状态与跨来源分歧：当核验偏差超过阈值时显示各来源原始值和差异，不静默覆盖本地计算。

### 3.4 除息日历

- 展示**未来 90 天**的自选标的除息安排，以**时间线列表**形式按日期排序，不做月历。
- 仅对公告确实确认的除息日期绘制确定时间节点；预案未公布日期时在“待定/预案”分区展示，禁止自行推算日期。
- 支持按 ETF/股票类型隔离；点击事件进入详情，展示证券、金额、股权登记日（如有）、除息日、公告及校验状态。
- 可选展示已除息历史事件为灰色项，不能与未来已确认事件混淆。

### 3.5 历史 TTM 曲线

- 以真实**逐交易日**未复权价格、逐日 TTM 窗口和权益调整事件重新计算；绝不能把今天的TTM值填充为整段历史。
- 支持 `1Y` / `3Y` / `5Y` 切换；历史长度不足时明确告知，而非画出缺失的平直线。
- 支持悬停/拖动横截面查看当日 TTM、价格、分红合计和具体日期；标识所选窗口高低值及相关分红事件。
- 缺失区间必须断线并展示原因，不能自动连线以掩盖无数据。
- 提供数据覆盖范围、更新时间及两种历史查询模式的口径标记；若数据不足，先展示“不完整+原因”，不输出伪精确曲线。

### 3.6 数据反馈与外观

- 复用现有 UI 规范和 `web/styles.css`，不重做其他页面；手机、桌面使用同一套业务 API。
- 请求加载、空状态、失败/重试、后台同步部分成功及数据过期要各有可理解的文案。
- 统一以“正常 / 待更新 / 数据不完整 / 校验失败 / 建设中”等状态展示；状态的含义和计算阻断规则必须在前后端一致。
- 图表/数字均可追溯观察时点和口径；不可用显示 `—`，不自动转换成 `0`。

## 4. 数据源、证据与采集合同

### 4.1 原始业务数据

| 数据 | 候选渠道（来自早期方案） | 首要校验与用途 |
|---|---|---|
| 实时/日终行情 | 腾讯行情；可使用经验证的其他市场行情适配器 | 交易所、证券代码、证券类型、币种、未复权口径、交易日与时间戳 |
| A股分红事件候选清单 | 东方财富 `RPT_SHAREBONUS_DET` 等 | 识别公告阶段、每10股金额、登记日、除息日；以正式公告核准关键字段 |
| ETF 分红事件候选清单 | 基金管理人公告；东财基金分红历史 | 原始“每份/每10份”单位、现金金额、除息日、分红版本；以基金正式公告为准 |
| A股正式分红公告 | 巨潮资讯、交易所正式公告 | “权益分派实施公告”及补充/修订公告的原始证据 |
| ETF 正式分红公告 | 交易所、基金管理人正式公告 | 基金分红公告的原始证据 |
| 未复权历史日K | 腾讯/AKShare适配器等，须单独实测可用性 | 逐交易日价格、停牌/除权及同日单位基准一致性 |
| 财报与支付率（后续 P1/P2） | 上市公司财报及核验后的财务数据适配器 | 股票所属年度、净利润/现金流对账和可选估算 |

说明：以上为**候选与历史选型**，不表示在当前执行环境中已验证持续可用。不得把镜像页/二次转载自动当作官方原文。采集渠道若失效，必须留有失败证据和错误说明。

### 4.2 数据源稳定性（禁止无声切换）

- 每类数据定义优先源、备选源、适用证券类型、字段映射、复权和币种口径。
- 记录每条数据的 `source_id`、抓取时刻、原始记录摘要、字段转换版本；数据源切换必须明确记录并触发口径一致性检查。
- **不允许在源A失败后静默切换源B并把数据当成源A**。必要时提供显式回退状态；口径未核验则停止计算。
- 对同一证券跨源数据进行代码/市场/类型匹配、单位、价格口径和时间对齐校验。
- 历史数据同步使用增量/幂等写入，不能重新抓取时产生重复分红事件。

### 4.3 分红事件账本与不可变证据

至少维持以下概念：

1. `security`：市场+类型+代码组成的稳定证券主键；保留重命名/退市/基金变化所需字段。
2. `dividend_event`：同一经济分红事件的唯一标识、归属财年、除息日、标准化现金金额、当前有效状态。
3. `dividend_revision`：预案、修订、实施公告的多个版本，包含原始单位与金额、公告/可知时间、证据关联及版本有效关系。
4. `source_document`：发布主体、原始标题、URL、公告日期、获取日期、原文文件、SHA-256、解析器版本和验证等级。
5. `raw_source_record`：完整原始响应/PDF元数据、抓取时间、哈希；原则上追加式保存，不覆写旧证据。
6. `quote`、`corporate_action`、`verification_run`、`watchlist`：分别保存价格、权益事件、核验执行报告和本地自选。

时间字段严格区分：

- `ex_date`：现金分红的经济生效日。
- `disclosed_at`：公告披露日期。
- `known_at`：市场最早可合理获得该公告版本的时间（如无精确时间，至少日期级并谨慎处理当日回测）。
- `observed_at/fetched_at`：本机抓取时间。
- `trade_date`：行情所对应交易日。

**所有正式对外展示的收益率均能向下追溯到事件版本、原始材料及报价；不能只存一个计算结果百分比。**

### 4.4 三级核验

| 层级 | 做法 | 通过标准或失败行为 |
|---|---|---|
| 一级：自动交叉核验 | 本地事件重算TTM与可核对同口径的第三方字段比较 | 历史需求使用 `0.3` **百分点**作为提示阈值；超过显示警告、各源值与时间，不直接覆盖；来源若不是同一TTM定义，不得生硬比较 |
| 二级：财报量级对账（P1） | 股票在具备会计期间、现金支付期间等信息时，按现金分配与相关财报/现金流数据进行量级核验 | 历史方案有 `±5%` 的辅助排查阈值；科目与支付时点可能不同，不能当作严格会计恒等式或以此替代公告 |
| 三级：原始公告复核 | 给出基金/交易所/巨潮的公告原件与字段定位；记录校验员或自动解析版本 | 官方材料不匹配、不可获取或关键字段不一致时，阻断对应数值并展示原因 |

交叉验证失败 ≠ 一定是本地公式错误；须先排查口径、日期、单位、复权和股本/份额变化。最终检验的是**数字可重算且经济含义一致**，而非强制凑成第三方某个页面的值。

### 5.3 数据迁移、幂等与错误处理

- SQLite 使用可重入、向前兼容的迁移方式；再次执行不能重复建表、丢失自选或覆盖现有资金流向数据。
- 所有原始金额、价格和分红计算结果都保留明确的十进制精度和单位，序列化规则统一。
- 外部接口超时/限流/响应结构变化/空值/乱码/验证码/防护HTML等，须显式失败并留日志，不允许当成“证券未分红”。
- 缓存和离线展示需要独立提示源数据日期；缓存可用不等于已经刷新成功。
- 手动批量刷新返回逐标的成功、失败、部分完成及原因；失败不应覆盖此前**可追溯**的有效历史结果，但过期数据不得冒充今日新值。
- 保护静态目录和数据目录的公开边界；避免为修复本模块破坏已有静态图表资源访问。
