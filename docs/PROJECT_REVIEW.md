# A股 ETF 看板项目复盘

## 1. 项目概览

本项目是一个本地运行的 A 股 ETF / 指数轮动分析看板，支持：

- 选择基准日期，并自动取该日期及之前最近的交易日；
- 查看累计收益、相对比值、布林带、收益差和 RSI 等指标；
- 在同一页面切换多个轮动策略；
- 通过本地服务按钮刷新数据，并以 SQLite 保存历史数据；
- 下载当前策略计算结果为 CSV。

当前看板名称为“ A股ETF看板 ”，数据更新服务运行在本机，前端通过 FastAPI 接口读取数据。

```text
红利累计收益率_t = 红利收盘价_t / 红利基准日收盘价 - 1
```

这里的 50:50 组合是按两个 ETF 的价格收益率等权计算，暂未加入交易费用、分红再投资、滑点和调仓成本。

## 3. 三棱镜指标公式

设 A、B 为两个指数的全收益指数点位，`t0` 为实际基准交易日。

### 3.1 同基准累计收益

```text
A累计收益_t = A_t / A_t0 - 1
B累计收益_t = B_t / B_t0 - 1
```

其中，用户可以输入任意日期。如果输入日期不是交易日，系统会自动选择该日期之前最近的交易日作为 `t0`。

### 3.2 A/B 比值

```text
Ratio_t = A_t / B_t
```

比值用于观察两个资产的相对强弱，不等同于 A 或 B 的绝对涨跌幅。比值上升表示 A 相对 B 走强，下降表示 A 相对 B 走弱。

### 3.3 242 日均线和布林带

对比值使用最近 242 个交易日计算：

```text
MA242_t = mean(Ratio_t-241, ..., Ratio_t)
σ242_t = sample_std(Ratio_t-241, ..., Ratio_t, ddof=1)
上轨_t = MA242_t + 2 × σ242_t
下轨_t = MA242_t - 2 × σ242_t
```

布林带阴影区域严格定义为 `[下轨_t, 上轨_t]`，也就是均线两侧的 `±2σ` 区间。由于上轨和下轨都使用同一个 `MA242_t` 和同一个 `σ242_t`，在同一交易日两条轨线到均线的距离应完全对称。

数据不足 242 个有效比值时，不显示对应的均线、上下轨和阴影，避免用不完整窗口制造误导。

### 3.4 40 日收益差

```text
A40_t = A_t / A_t-40 - 1
B40_t = B_t / B_t-40 - 1
收益差40_t = A40_t - B40_t
```

再对 `收益差40_t` 计算 242 日均线：

```text
收益差均线242_t = mean(最近242个有效的收益差40值)
```

该指标反映近期 A 相对 B 的阶段性强弱，以及这种强弱是否高于或低于长期平均水平。

### 3.5 比值 RSI14 和长期均线

RSI 计算对象是 `Ratio_t`，不是分别对 A、B 计算 RSI。

```text
Change_t = Ratio_t - Ratio_t-1
Gain_t = max(Change_t, 0)
Loss_t = max(-Change_t, 0)
```

采用 Wilder 平滑：

```text
AvgGain_t = (AvgGain_t-1 × 13 + Gain_t) / 14
AvgLoss_t = (AvgLoss_t-1 × 13 + Loss_t) / 14
RS_t = AvgGain_t / AvgLoss_t
RSI14_t = 100 - 100 / (1 + RS_t)
```

当 `AvgLoss_t = 0` 时，RSI 取 100。RSI 的长期参考线为：

```text
RSI均线242_t = mean(最近242个有效的 RSI14 值)
```

## 4. 数据来源与数据处理

### 4.1 数据来源优先级

项目当前采用以下优先级：

1. 优先使用 ETFirst；
2. ETFirst 不可用、服务无法访问或没有返回历史数据时，使用 AkShare；
3. ETF 数据通过 AkShare 的 ETF 历史行情接口获取；
4. 指数全收益数据通过 AkShare 的中证指数历史接口获取。

ETF First 依赖外部服务，GitHub Actions 环境无法稳定访问，因此 GitHub 部署时不能把 ETFirst 作为唯一数据源。AkShare 作为本地和自动更新场景下的备用来源。

### 4.2 ETF 与全收益指数的区别

- ETF 数据是交易产品的市场收盘价，受到折溢价、基金费用、跟踪误差和交易流动性的影响；
- 价格指数通常只反映成分股价格变化；
- 全收益指数在价格变化之外，还假设分红按指数规则进行再投资；
- 三棱镜策略使用的是指数全收益代码，因此更适合做长期相对收益比较；
- ETF 看板使用 ETF 收盘价，更接近实际可交易产品的表现。

### 4.3 起始日期和历史长度

数据更新会根据本地已有数据的最新交易日进行增量获取。首次更新时，从配置的起始日期或指数/产品可获得的最早历史日期开始下载；之后只请求最新日期之后的数据。

如果某个日期早于产品成立日或数据源最早可用日期，则以数据源返回的第一条有效记录为准，不人为补造数据。

### 4.4 SQLite 与 JSON

SQLite 是主要的数据存储：

- `data/etf_market.db`：保存 ETF 和指数的历史价格；
- `etf_prices`：ETF 日收盘数据；
- `index_prices`：指数全收益日数据。

JSON 文件是用于前端静态读取、调试和部署的快照：

- `data/etf_prices.json`
- `data/index_prices.json`

更新流程通常是：拉取新增数据 → 清洗日期和数值 → 按代码与日期去重 → 写入 SQLite → 导出 JSON 快照 → 前端重新读取。

## 5. 基准日和前端状态

每个看板拥有独立的基准日期，不同看板之间互不联动。基准日期会保存到浏览器 `localStorage`，因此重新打开页面时会恢复该看板上次使用的日期，而不是强制恢复到 2025-12-31。

基准日计算规则：

```text
实际基准日 = max({交易日 | 交易日 <= 用户输入日期})
```

切换基准日后，卡片、图表、累计收益、差值和下载数据应全部使用新的实际基准交易日重新计算。

## 6. 本地更新服务和使用方式

本地服务入口为 `server.py`，启动命令：

```powershell
python -m uvicorn server:app --host 127.0.0.1 --port 8000
```

打开：

```text
http://127.0.0.1:8000/web/
```

点击页面中的“刷新数据”按钮后，前端调用本地 `/api/update`，服务端执行增量更新并返回最新数据。这样日常使用不需要手工输入命令行更新数据。

如果网络环境需要代理，应在当前 PowerShell 窗口中设置，例如：

```powershell
$env:HTTP_PROXY = "http://127.0.0.1:7890"
$env:HTTPS_PROXY = "http://127.0.0.1:7890"
$env:ALL_PROXY = "http://127.0.0.1:7890"
$env:NO_PROXY = ""
```

上述命令必须在 PowerShell 中执行，不能直接粘贴到普通 CMD 提示符中。

## 7. 已知限制与后续方向

- 当前 ETF 50:50 组合是简单等权收益，不包含真实调仓时点和交易成本；
- 三棱镜目前展示信号指标，尚未把指标阈值转化为完整的自动交易回测；
- ETFirst 的可用性依赖外部服务，生产部署应保留 AkShare 或其他稳定数据源；
- GitHub Pages 只能展示静态结果，不能直接运行本地 FastAPI 或安全保存私密 API key；
- 后续可以增加信号规则、调仓周期、权重、交易成本、回测净值和策略对比；
- 增加新策略时，只需新增 A/B 指数代码、中文名称和策略配置，复用同一套三棱镜计算逻辑。

## 8. 复盘时的检查清单

1. 确认指数代码对应的是价格指数还是全收益指数；
2. 确认 A、B 数据日期已对齐，且没有把非交易日当成有效点位；
3. 检查基准日期是否被映射到前一交易日；
4. 检查布林带是否满足 `上轨 - 均线 = 均线 - 下轨 = 2σ`；
5. 检查 242 日指标是否只有在窗口完整时才显示；
6. 检查 RSI 的输入是否为 A/B 比值，而不是单独的 A 或 B；
7. 记录数据更新时间、数据源和异常回退情况；
8. 将策略信号、调仓规则和实际交易结果分开记录，避免把指标图误当成已实现收益。
