# 工程修复摘要（2026-11-13）

## P0 运行可靠性

- `scripts/snapshot.py` 统一解析 Windows、POSIX 和混合路径，拒绝盘符、绝对路径、路径穿越与越界链接，并校验 SHA-256、版本和关键结构。新 Manifest 使用 POSIX 相对路径；旧文件不批量改写。
- `/api/health` 增加三级状态和检查明细；`/api/live`、`/api/ready`、`/api/freshness` 分开报告存活、可读与新鲜度。启动时检查待恢复发布。
- Windows 与真实 WSL Linux 环境均读取同一旧 Manifest，核心快照及业务 API 返回 200。

## P1 数据、发布与计算

- ETF 首选 AkShare/东方财富。新浪回退先留原始证据并隔离；只有逐标的配置经过人工口径审核的证据 ID、同口径主源重叠样本、真实原始文件哈希、价格差和区间收益差全部通过，才允许入选。配置缺失或比较失败时旧快照继续服务。
- 新批次的原始记录、行情、规范化选择链接、质量问题及 prepared 标记在一个 SQLite 事务内提交。先写并校验发布文件，再提交数据库，最后切换 Manifest。刷新使用跨进程锁；启动或下次刷新可完成有效 prepared 发布，无法对账时阻断刷新并保留旧指针。
- 溯源 API 报告选择链接；历史无链接的记录保持 `UNKNOWN`，仅显示哈希匹配的旁证原始记录，不冒称其为当年的实际选择。
- A/H 回测共用持仓、现金、费用和次共同收盘执行规则；初始建仓收取费用。补充可手算与边界测试。

## P2 界面与工程

- 主看板显示截止日、快照、来源核验、收益口径和质量状态；50:50 明确标为“初始各 50% 买入持有”。保留四条累计收益曲线及一组收益差柱状图在同一 ECharts 复合图。刷新后在用户跟随最新日期时同步更新日期筛选。
- 七个页面经 1440、768、390 像素浏览器实测：均可加载、无页面异常或整体横向溢出；主要移动端筛选、导航、表格展开和说明弹层可操作。
- 新增只读空间清单与清理预览命令。后续核对发现两套 AkShare 重建备份逐文件完全相同，已删除其中一套；当前数据库、历史发布快照及原始证据未删除。详见 `storage-cleanup.md`。
