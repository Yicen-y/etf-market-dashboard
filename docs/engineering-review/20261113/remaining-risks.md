# 剩余风险与后续处理（2026-11-13）

1. **历史溯源**：52,641 条旧规范化行情没有 `selected_raw_id`。只读哈希匹配可提供旁证，但不能证明当时的选择链。AkShare 归档的是返回表序列化结果，无法由此恢复上游 HTTP 原始响应。任何批量补链都应先备份数据库、逐批核实归档表及解析版本，并准备恢复方案；无法确认的保持 `UNKNOWN`。
2. **备用源真正上线**：当前没有独立确认新浪未复权定义、现金分红/拆并份处理及差异的审核证据，也没有已启用的 `source_policy.json`。代码允许有证据的同口径重叠校验；实际启用仍需金融数据人工审核，主源恢复后的历史修订对账也需演练。指数 ETFirst/AkShare 回退尚未建立同等级价格/全收益口径闸门。
3. **跨资源恢复边界**：已覆盖 SQLite 失败、Manifest 切换失败和 prepared 恢复。数据库与文件系统仍不具备跨资源 ACID；需在生产等价目录实测磁盘写入失败、断电和人工回滚，确认备份与恢复操作手册。
4. **策略人工基准**：A/H 回测已加入手算与边界案例。三棱镜、五年之锚、资金流、股息率及 50:50 组合仍需逐模块补齐独立手算案例、历史回归、输入口径证明；不能把现有单元测试等同于这些金融口径的独立核验。
5. **界面状态一致性**：主看板已有状态条，其他页面各自显示部分日期、来源或质量信息，尚未统一成覆盖“陈旧、缺失、来源异常、更新中、更新失败”的共享组件。浏览器宽度和基础交互已验收；复杂 Tooltip 遮挡及金融异常事件标注仍需按页面细查。
6. **保留策略**：一套完全重复的备份已删除。其余备份与历史快照内容不同，部分旧快照被研究报告引用；当前无临时清理候选。未来可定义至少保留当前版本、已验哈希的回滚版本和完整原始证据的窗口，再单独评估清理。
