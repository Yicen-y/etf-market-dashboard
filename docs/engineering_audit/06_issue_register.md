### A01 命令行正常刷新默认绕过指数参考门禁｜数据正确性｜已确认代码缺陷

- **位置/触发**：`scripts/update_data.py:331-336,655-669,843-855`；用户执行 README 推荐的 `python -m scripts.update_data`，且遇到新增/变化指数点位。

- **验收**：在临时数据目录注入新增候选且无参考证据，CLI/API/每日入口均拒绝发布；Manifest 哈希与 SQLite 正式行情不变；有有效参考时三入口一致通过。

## P2 中

### A02 核验状态没有准确传播到来源 API｜数据可追溯性｜已确认代码问题

- **位置/触发**：`scripts/update_data.py:806-807`、`server.py:487-490`；严格门禁成功发布后查询该日来源。
- **证据/影响**：规范记录仍统一写 `fact_verified=False`、`STRUCTURE_PASS_SOURCE_UNVERIFIED`；API 只给 `UNVERIFIED/UNKNOWN`。会掩盖“点位已匹配但身份仍待证”等实际层级，影响使用者判断证据强度；不是证明点位错误。
- **整改/风险**：在不改金融值的前提下分离结构、数值匹配、身份三个状态，API 从现有逐日证据取状态；需防止把供应商匹配误标为编制机构身份确认。
- **验收**：固定三类样本分别返回匹配/身份未证/无证据，且 UI 标签与数据中心一致。

### A03 指数快照整包传输与解析成本明确｜性能｜实测瓶颈

- **位置/触发**：`server.py:509-520`、`web/app.js:25-35`；首次进入指数看板或刷新快照。
- **证据/影响**：现有快照 `ensure_ascii=False` JSON 估算 20,376,803 B，实际 TestClient HTTP 响应 18,768,125 B；3,087 日；本机只读函数中位 378.31 ms，隔离副本 API 12 次 P50 809.06 ms、样本 P95 904.64 ms。未测真实网络/浏览器，不能断言用户端超过某阈值。
- **整改/风险**：先测浏览器瀑布，再按策略/系列/区间读有界数据；保持相同快照 ID 和公式版本。风险为前端误用不同版本/不同日历。
- **验收**：同快照逐点结果一致；测量接口字节、服务端耗时、首图完成时间，改进量以实测为准。

### A04 轮动总览每次请求重复读取和计算｜性能｜实测瓶颈

- **证据/影响**：纯 `build_overview` 12 次中位 335.36 ms，且路由每次再读两份快照；隔离副本 API 12 次 P50 749.14 ms、样本 P95 843.73 ms。单用户也会在页面重载时支付重复成本；未测真实网络。
