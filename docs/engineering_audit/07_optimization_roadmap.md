# 分阶段整改路线

估算为单人净开发时间，未含等待外部数据源；每项可独立提交、测试、回滚。范围均不扩张投资功能。

| 阶段/任务 | 模块与前置依赖 | 工作量 | 风险与回滚 | 验收 | 数据库/算法 |
|---|---|---:|---|---|---|
| 1. A01 统一所有发布入口门禁 | `update_data.py`、README、CLI/API/每日任务测试；无需前置 | 0.5–1 天 | 官方参考不可用时更新被阻断；回滚代码即可，旧快照保留 | 无参考的新增点在三入口均不能发布；有参考正常发布 | 不改结构/公式 |
| 1. A02 校正核验层级传播 | `update_data.py`、`server.py`、数据中心；依赖 A01 语义确定 | 1–2 天 | 状态迁移可能误标历史；先只读派生、必要时保持 UNKNOWN | 数值匹配、身份未证、未知三种样本分别准确 | 优先不改库；如需新增字段须另审 |
| 1. A08 盘点旧镜像读者 | `storage.py`、本地脚本；无需前置 | 0.5–1 天 | 外部脚本兼容；先清点再改 | 发布中断注入后主 API 与恢复一致 | 不改结构/公式 |
| 2. A03 指数有界查询 | `server.py`、快照读取、`web/app.js`；先取得 HTTP/浏览器基线 | 2–4 天 | 不同快照/日历混用；按快照 ID 验证逐点一致并可回滚到整包 | 体积、接口 P50/P95、首图完成时间实测改善；数值一致 | 不改库/公式 |
| 2. A04 总览快照键缓存 | `server.py`、`rotation_overview.py`；独立 | 0.5–1 天 | 旧缓存；以 ID+公式版本键控 | 冷热哈希一致、换快照自动失效、延迟实测 | 不改库/公式 |
| 2. A05 分红历史批量读 | `dividend/service.py`；先记录 SQL 基线 | 1–2 天 | 观察日/公告版本边界；黄金样本逐点比对 | 1Y/3Y/5Y 值与空因一致、查询次数下降 | 不改库/公式 |
| 2. A06 更新过程局部拆分 | `update_data.py`；在 A01 后 | 2–3 天 | 失败路径回归；每次仅抽一个纯逻辑单元 | 既有故障注入/隔离循环全过 | 不改库/公式 |
| 3. A09 复合图单位提示 | `web/app.js`、图表主题；依赖固定截图夹具 | 0.5–1 天 | 双轴误导；保持单图和零线 | 两种单位在图例、轴、Tooltip 清楚；手机可读 | 不改库/公式 |
| 3. A07 前端渐进拆分与状态文案 | `web/app.js`、状态组件；先有固定 UI 样本 | 2–3 天 | 图表联动退化；小步回滚 | 策略/日期/缩放/错误态回归通过 | 不改库/公式 |
| 4. A10 固定数据交互回归 | `tests/ui_*`、CI；可与阶段 3 同步 | 1–2 天 | CI 环境波动；本地结果先稳定 | 主图/资金流/分红三条链路的数值、单位、状态、空态通过 | 不改库/公式 |
| 4. 观测与维护 | 现有日志/任务状态、性能采样；在 2 阶段测量后 | 1–2 天 | 日志过量；仅记耗时/计数/快照 ID，不记凭证 | 更新与核心查询可分段定位；异常保留旧快照 | 不改库/公式 |

推荐下一轮 Codex 先单独实施 **A01**。交付应只包含入口默认值/文档/隔离测试，避免同时触碰金融公式或数据库。随后 A02、A04 可独立进行。缓存、分页或有界查询的收益在真实 HTTP 和浏览器测量后才定量报告。
