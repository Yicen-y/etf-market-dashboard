# A07/A09 浏览器性能与交互对比

## 测试环境和方法

2026-11-18，本机 Windows、Chrome Headless、Playwright；桌面 1440×900，手机 375×812。`tests/ui_a07_a09_browser.py` 先以 SQLite Backup API 复制数据库，再复制当前 Manifest 指向的 ETF/指数 release 到临时目录，通过 `ETF_DATA_DIR` 启动本地 FastAPI。每页在新浏览器 context 中导航，计时从 `goto` 前到关键结果可见后 150 ms；记录 GET API 响应体字节数、页面异常、ECharts 配置、截图。测试不调用数据更新接口，也不写真实历史数据。**前后每场景各一次，不代表 P50/P95，数十至数百毫秒变化不能归因于本轮改动。**原始记录：[优化前 JSON](evidence/before_browser_metrics.json)、[优化后 JSON](evidence/after_browser_metrics.json)。

## A03/A04/A08 与交互结果

- A03：ETF 页只取 ETF 数据 620,166 B 与 `etf-index` 投影 307,961 B；三棱镜只取对应投影 1,161,965 B；配置策略只取对应投影 2,027,929 B。主页面未取 18.8 MB 全指数响应。时间筛选不额外请求，`全部`范围仍可显示历史，旧完整 API 未改。
- A04：总览一次 GET `rotation/overview`，8,837 B；本轮未改总览缓存。现有 UI 脚本验证总览质量筛选、事件期和手机菜单；所有组完整时显示一行空状态。
- A08：一次 409 注入后同策略请求共 2 次，Manifest 共 2 次（初始及重取），图表恢复且消息不再可见。隔离目录真实发布新版本后，旧 ID 请求 409、新 ID 请求 200，页面 `activeSnapshotId` 与图表数据 ID 均为新版本。持续 409 恰好请求两次并显示错误，无无限重试。
- 主图、全收益指数图各保留 1 条收益差柱；Tooltip 固定样本同时呈现 `+20.00pp` 与 `+10.00%`；图例与曲线/柱序列保留。现有浏览器脚本通过三棱镜范围、基准日、CSV、ETF、资金流与五年之锚表格、总览筛选及手机导航。

## 结论与限制

**本轮不能证明前端速度改善。** API 次数和体积未增加，页面就绪及交互的单次差异处在未控制的机器/服务波动中；本轮收益是 409 自动恢复与复合图单位辨识。截图：[ETF 改前](evidence/before_etf_desktop.png) / [改后](evidence/after_etf_desktop.png)、[改后主图](evidence/after_etf_chart.png)、[改后全收益图](evidence/after_index_chart.png)、[三棱镜](evidence/after_prism_desktop.png)、[资金流](evidence/after_flow_desktop.png)、[五年之锚](evidence/after_anchor_desktop.png)、[手机](evidence/after_etf_mobile.png)、[版本切换](evidence/after_version_switch.png)。未测 Firefox/Safari、真实 WAN、真实更新任务、连续多次发布或长时间运行的资源曲线。
