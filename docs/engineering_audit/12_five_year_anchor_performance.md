# 五年之锚端到端性能测量

## 结论与根因

默认视图只显示 H20903，但原 `web/anchor.js` 的 `load()` 除日经视图外恒传 `index_code=all`。服务器因此计算并返回 H20903、H00922 两套完整指标及对比数据，浏览器只画其中一套。2,271,081 B 本身并非唯一瓶颈；在本机，API 阶段 P50 为 1,358.80 ms，约占冷启动图表就绪 P50 1,872.79 ms 的 73%（两个中位数之比，仅用于量级判断）。JSON 解析 P50 6.0 ms、图表 `render()` P50 83.3 ms，均小得多。响应体积和服务器双指数计算共同造成等待，不能把全部节约归因于网络字节数。

已将请求参数改为当前视图的指数代码，双指数对比仍请求 `all`；保留每个指数的完整 3,368 行历史数据。用户切换历史区间只改变 ECharts 的 `dataZoom`，不会重新请求或截断指标。没有改动计算公式、数据精度或后端协议。

## 环境与复现方法

- Windows 本机，Python 3.9.13，Headless Google Chrome 157.0.8103.79，Playwright，视口 1440×900 CSS px。
- 固定 Manifest `20261117T211724-1c548b20`。脚本用 SQLite backup 和文件复制生成临时数据目录，再启动隔离 Uvicorn；不更新真实历史数据。
- 同一台机器、同一浏览器版本、同一数据版本、同一脚本先测修改前再测修改后。每组 5 次。冷启动＝新浏览器 context；热启动＝同一 context 内重新进入新页面、可使用 HTTP 缓存。API P95 为 5 个样本的 nearest-rank 最大值，样本小，不代表生产长尾 SLA。
- 页面就绪：从 `page.goto()` 开始，到指标图 ECharts 完成 `setOption()` 后再经过两个 `requestAnimationFrame`，同时观察到指标摘要。`PerformanceResourceTiming` 量 API；`response.text()` 与 `JSON.parse()` 分开插桩；记录数据序列准备、配置、`setOption()`、`render()`、JS heap 和 Long Task。插桩方式对前后完全相同；阶段可能重叠，不能直接求和。
- 命令：`python -B tests/bench_frontend_round2.py before` / `python -B tests/bench_frontend_round2.py after`。原始数据：[修改前](evidence/before_frontend_round2.json)、[修改后](evidence/after_frontend_round2.json)；[修改前 Trace](evidence/before_anchor_trace.zip)、[修改后 Trace](evidence/after_anchor_trace.zip)。

服务端直接请求的对照：`all` P50/P95 修改前 1,144.83/1,267.69 ms、修改后 1,168.36/1,277.08 ms；单指数 H20903 修改前 784.50/939.10 ms、修改后 814.03/943.63 ms。两种接口本身没有系统性加速，改善来自默认页面选用现有单指数能力。浏览器 API 耗时与直接请求耗时计时边界不同，不能互换。

长任务仍存在：冷页每次 2–4 个、总时长 P50 修改前 238 ms、修改后 279 ms；最大单个 104/101 ms。这个波动没有显示出明确改善，不能称为长任务优化。热页总时长 P50 398→300 ms。当前 ECharts 绘图约 80 ms，未见反复销毁实例；继续拆分计算或降精度缺少收益证据。

## 结果一致性与限制

隔离 API 对照确认：H20903、H00922 单指数响应中的对应 `indexes[code]` 与 `all` 响应逐项相等，snapshot_id 相同；两者均有 3,368 行，2012-12-31 至 2026-11-17。浏览器切换 H20903→H00922→双指数对应发出 3 个正确代码请求；“全部”范围覆盖首末行，无 JS 错误。见 [回归证据](evidence/round2_regression.json)。日期筛选仍使用保留的完整序列，图表实例未重建。

首个冷样本包含浏览器及服务端启动后的额外波动；P95 受此影响明显。测试是本机固定快照的相对对照，未覆盖移动设备、弱网及大并发。`JSON.parse` 插桩替换了 `response.json()` 的调用形式用于测量，但两者的数据语义一致；生产代码仍用 `response.json()`。
