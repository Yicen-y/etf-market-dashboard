# 纳指100 ETF 溢价率监测模块——开发需求与验收合同

版本：2026-11-04  
目标工程：`etf-market-dashboard`（本地 FastAPI + SQLite + HTML/ECharts，单用户使用）

## 一、任务目标与优先级

在现有投资分析看板中新增一个独立的「纳指100 ETF 溢价率」模块。**不是**根据基金价格和 NAV/IOPV 重新计算溢价率。应优先调用南方基金 **ETFirst**，获取 ETF 产品本身已计算好的溢价率字段，然后进行两种不同类型的统计聚合。

1. **全市场横截面模式**：每天对沪深交易所全部有效的、跟踪 NASDAQ-100（纳斯达克100）指数的 ETF 计算溢价率简单均值、最高值、最低值，形成三条历史曲线。
2. **单只 ETF 历史模式**：选定某一只 ETF 与历史时间范围后，展示该基金每个交易日的原始溢价率曲线，同时计算**所选区间**的平均值、最高值、最低值，显示于三个 KPI 卡片和图上的参考水平线；极值注明发生日期。
3. 对每条数据展示原始来源、数据时间、溢价口径、当日样本覆盖情况；未取得历史数据时不得模拟或凭空补齐。
4. 首次进入页面默认「全市场」+「近6个月」；支持近1个月、3个月、6个月、1年、全部、自定义日期区间。区间统计应随筛选动态变化。

注意：单只 ETF 每交易日若只有一个日频溢价率数据点，则“当天最高／最低／平均”均等于当天该值，没有区分价值。**不要**把单只日频数据画成三条相同的曲线。除非未来已采集多个盘中快照，否则单只模式的三指标应按**所选历史区间**统计。

## 二、数据源调查——必须先完成，不允许猜测接口

项目现有代码：

- `scripts/fetch_data.py` 已实现 `fetch_product_history_etfirst`，通过 `etfirst --json etf-detail all --product-code ... --start-date ... --end-date ...` 获取 ETF **历史收盘价格**。
- 此功能不能证明同一命令也能返回**溢价率**；不要将返回的历史价格或走势字段当成溢价率。
- `README.md` 已说明 ETFirst 客户端安装与 `etfirst auth login --api-key` 的配置方式。

请先在用户已配置 API Key 的本地环境操作：

1. 运行 `etfirst --help`；查询与 ETF 溢价、实时折溢价、ETF 筛选、历史溢价率有关的官方命令、参数、调用限制。
2. 以 `513100` 和 `159513` 为测试标的，分别测试**当日/最新**与**历史区间**能否返回直接的溢价率。保存一份**脱敏后的原始 JSON 样例**与字段映射表，注明提供的数据是盘中 IOPV 溢价还是对正式单位净值的溢价。
3. 检验能否批量查询，是否返回全部纳指100基金产品。若需要分产品查询，使用限速与重试，避免无故过载。
4. 如果 ETFirst 支持“实时但不支持历史溢价”，必须在界面展示真实历史覆盖起点；可以启动每日收盘后定时采集建立自己的历史数据，亦可以在另行验证了**同一溢价率口径**的合规第三方数据源后进行历史回填。不同口径不可直接拼接成一条未加说明的曲线。
5. 如果不支持直接返回溢价率，不得偷偷回退到 `(收盘价/NAV)-1` 并声称它来自 ETFirst；提供清晰的 `source_unavailable` 或 `field_missing` 状态，再考虑返回原生折溢价率的其他数据提供方。
6. **不可假设**本地已经有 ETFirst 或 API Key，导入模块与启动服务时必须在没有密钥的情况下正常运行。没有实盘数据时页面明确显示“未取得溢价率数据”。

## 三、ETF 产品池

限定为上海/深圳证券交易所上市、实际追踪 NASDAQ-100 指数的 ETF；不包括纳斯达克科技ETF、纳斯达克生物科技ETF、不跟踪该指数的类似基金、场内 LOF。产品池以真实标的指数、上市日期、退市日期和基金类型确定，不允许仅依基金简称包含“纳指”就纳入。

建立表 `nasdaq_etf_universe`：

- `fund_code`（含市场代码的标准化证券代码）
- `fund_name`
- `exchange`
- `fund_type`
- `benchmark_index_code`, `benchmark_index_name`
- `listed_date`, `delisted_date`
- `included`（是否纳入统计）
- `source`, `source_checked_at`

注意排除例子：`159509`（纳斯达克科技主题，不等于纳斯达克100）；`161130`（LOF，不是 ETF）。这些排除应有规则和可测试的断言，不应只靠名称人工硬编码。

实行动态样本池：每个交易日只汇总当天已上市、仍存续、符合基准指数条件的基金。提供手工触发产品池更新并记录新上市基金、退市基金的能力；市场走势页显示当日有效样本数量和应有样本数量。

## 四、原始数据表与单位约定

统一保存 ETFirst 返回的**原生溢价率**，不以价格重算。核心表 `nasdaq_premium_observations`：

| 字段 | 含义 |
| --- | --- |
| `fund_code` | ETF代码 |
| `trade_date` | 中国 A 股交易日 YYYY-MM-DD |
| `observed_at` | 原始报价时点/采集时点（带时区） |
| `premium_pct` | 溢价率百分数单位，例如 `12.5` 表示 +12.5% |
| `premium_basis` | `IOPV` / `NAV` / `UNKNOWN`；UNKNOWN 不得自动合并到正式比较序列 |
| `snapshot_type` | `intraday` / `eod` / `historical` |
| `price_asof`, `nav_asof` | 若上游提供，则记录价/净值时点 |
| `turnover` | 可选：当日成交额 |
| `source_provider` | 来源，例如 `ETFirst` |
| `source_command` | 真实请求命令/接口（脱敏） |
| `fetched_at` | 本系统获取时间 |
| `raw_payload_ref` | 本地原始响应文件位置（脱敏） |
| `quality_status`, `quality_note` | 完整性、异常与时间戳检查结果 |

同一 ETF、交易日、同一口径和快照类型可有多个盘中采集点；每日汇总应选**同一收盘截止规则**的数据，不能将某只基金 10:30 的溢价率与另一只 15:00 的溢价率隐式混合。

明确标记 `+12.5%`、`-1.2%` 的符号，避免把“折价率字段”正负号直接当作溢价率。对不同上游字段必须先通过样本和官方释义验证百分数单位及符号，不允许推测 `0.12` 是 0.12% 还是 12%。

数据库应有必要的唯一约束、索引和增量 upsert；保留历史原始记录以便重新聚合、溯源和纠错。不得把无数据转成 0%。

## 五、聚合定义

设某交易日 `d` 具有 `N_d` 条合格的 ETF 溢价率 `p(i,d)`：

**全市场每日统计**：

- `market_avg(d) = sum(p(i,d)) / N_d`（简单平均，不按成交额加权）
- `market_min(d) = min_i p(i,d)`
- `market_max(d) = max_i p(i,d)`
- `min_fund_code(d)`, `max_fund_code(d)`：记录两侧极值归属
- `valid_count(d)`, `expected_count(d)`, `coverage(d)`：展示当天数据覆盖率

**单只 ETF 在选定区间 [a,b] 的统计**：

- `single_avg(i;a,b) = mean_{d in [a,b]} p(i,d)`
- `single_min(i;a,b) = min_{d in [a,b]} p(i,d)`
- `single_max(i;a,b) = max_{d in [a,b]} p(i,d)`
- `min_date`, `max_date`, `valid_days`：记录极值日期和有效交易日数量

默认仅纳入当日通过检查、口径一致且满足当日截止规则的记录。若覆盖率不足 80%（阈值作为设置项），该日全市场数据标为 `incomplete`，趋势图默认断点，不做插值；用户可明确切换“查看不完整样本”。无效或缺失日期一律不补零、不前向填充。

对全市场区间顶部三个 KPI：可展示所选期间 **日均市场溢价率**、**期间市场最高值**、**期间市场最低值**。区间日均是等权对有效交易日 `market_avg(d)` 再求平均；说明其与“所有 ETF×交易日记录的加权总体平均”不同。

## 六、界面设计

- 在现有左侧导航新增一个独立链接「纳指100 ETF 溢价率」，页面 `web/nasdaq-premium.html`，继续复用已有的页面布局、配色、排版、ECharts、控件规范；不破坏轮动、红利、资金流模块。
- 顶部：`全市场 | 单只 ETF` 分段切换、ETF 搜索/选择下拉框（在全市场模式禁用）、时间范围（1M/3M/6M/1Y/ALL）、自定义日期范围、刷新、下载 CSV。
- 3 个 KPI：平均溢价率、最高溢价率、最低溢价率。随模式和时间区间动态更新，明确使用的是“当日”还是“区间”口径。
- **全市场图（单图）**：同一 ECharts 坐标轴上三条曲线：最低、平均、最高。点击/悬停显示日期、3 个值、对应极值 ETF、样本数与覆盖率，可选最小-最大区间淡色带。不可将三条线拆成多个子图。
- **单只 ETF 图（单图）**：所选 ETF 每日原始溢价率一条曲线，叠加所选时间区间均值/最高/最低的三条可识别参考线（其中最高最低也可用 markPoint 显示实际极值日期）。不要把三个区间统计值伪装成“每日三条独立历史曲线”。
- 图下表格：全市场逐日 `日期/均值/最低/最低ETF/最高/最高ETF/样本数/覆盖率`；单只模式 `日期/ETF名称/ETF代码/溢价率/来源/口径/报价时点`。
- 显示 `最近成功更新时点`、`最新交易日`、`数据源`、`口径`、`历史覆盖开始时间`，并提供 ETFirst 失败、历史数据不可得、样本缺失、时间错位的可见状态提示。

## 七、后端接口与代码分层

建议新增 `scripts/nasdaq_premium/` 领域包并复用现有数据库：

- `universe.py`：产品池规则和存续日期
- `providers/etfirst.py`：原生命令调用/字段校验/批量查询，仅接收真实源数据
- `models.py`：记录模型/数据单位/异常状态
- `db.py`：SQLite schema、upsert、查历史
- `service.py`：日期对齐、聚合、质量检查、区间过滤
- `api.py`：FastAPI APIRouter
- `sync.py`：增量同步、历史回填与任务调度的入口

建议 API（可根据工程约定微调）：

- `GET /api/nasdaq-premium/universe`
- `GET /api/nasdaq-premium/market?start=YYYY-MM-DD&end=YYYY-MM-DD&basis=NAV`
- `GET /api/nasdaq-premium/fund/{code}?start=...&end=...&basis=NAV`
- `GET /api/nasdaq-premium/status`
- `POST /api/nasdaq-premium/sync`：仅在本地运行时允许，不能暴露密钥/凭证

`server.py` 注册 router；保留单用户本地部署，不新增账号、权限、云数据库或账户系统。前端复用 `web/echarts.min.js`、`web/styles.css`；遵循现有 SQLite 使用约定。

## 八、优先级和可验收标准

**P0——先证实 ETFirst 能力，再写业务代码**

- 有真实的 ETFirst CLI help 信息、返回 JSON（已脱敏）、字段含义、单位、可回溯范围和 API 请求结果。
- 证实当前 ETF 清单的准确性及排除项。
- 若缺失直接的 premium 字段，明确呈现不能按 ETFirst 实现的阻塞事实，不允许补造数据。

**P1——数据采集、规范化、聚合**

- 至少完成一批真实来源的基金记录入库，以及全市场/单只聚合。
- 单测覆盖：百分数单位与折溢价符号、极值归属、时间区间、基金上市前排除、停牌/缺值、日内/日终隔离、覆盖不足、重复同步幂等、负溢价率、极端值与原始来源追溯。
- 所有汇总值均可从原始值重新独立计算，结果误差不超过 `1e-9` 百分点（浮点运算层面）。

**P2——ECharts UI、CSV、历史自动积累**

- 全市场默认一张三曲线图；切换单只 ETF 后原始溢价率曲线+三项区间统计。
- 日期筛选、联动 KPI、悬浮提示、CSV 输出一致，图上显示实际日期。
- 采集失败不可覆盖已有已验证历史，不能悄悄使用过期结果装作当天。
- 未认证或 ETFirst 不可用时，页面仍可打开；显示明确信息，不展示伪数据。

**P3——历史回填（只有在数据源真正支持时做）**

- 若 ETFirst 有历史直接溢价率：按交易日批量回填并逐日比对；记录覆盖起止日期。
- 若只能提供实时：每日收盘后同步，并在界面明确说明“历史从首次采集起积累”；历史回填可另立任务寻找同口径合规数据源，严禁擅自把盘中 IOPV 溢价与 NAV 收盘溢价拼接。
